## 0. 一句话结论

**v1.4 没有动生存模型的任何一个数**。五轴速率、体温夹逼、昼夜周期与 v1.1 逐位相同。
它变的是**外围**：加了难度选择、两种胜利条件、大量美术与文本，以及一套 VIP 内容。

对我们的意义：**之前照着 v1.1 移植的数值不需要返工**，但 v1.4 的难度实现方式非常值得抄。

| | v1.1 | v1.4 |

## 3. v1.4 真正新增的东西

### 3.1 难度选择（四档）—— 最值得抄的一条

开局对话框选难度，实现方式只有一行：

```jass
// 简单：什么都不做
// 中等：SetPlayerTechResearchedSwap('R000', 现有等级 + 1, Player(11))
// 困难：           同上 + 2
// 挑战：           同上 + 3
```

`R000` 是一个挂在**敌方玩家 Player(11)** 身上的升级科技（名字就叫「难（1）/（2）/（3）」），
魔兽的科技系统会自动把加成套用到该玩家的**所有单位**上。

**这个做法的漂亮之处**：难度不是散落在几十个刷怪参数里的魔法数字，而是
**一个作用于敌方阵营的乘数**。加一档难度 = 敌人科技 +1 级，不用碰任何刷怪逻辑。

> 对我们的启发：我们现在的狼群强度散在 `getNightScaling()`（每夜 +3 攻 +12 血）里。
> 要加难度选择，最省事的做法就是给这个 scaling 乘一个难度系数，而不是复制四套刷怪表。
> 结合 v1.1 已经发现的「-A 生存模式用代谢翻倍而不是加怪来做难度」，
> 原作者在难度这件事上有两套互补的手法：**改敌人强度** 和 **改玩家代谢**。

### 3.2 两种胜利条件

选完难度再选模式：

| 模式 | 热键 | 含义 |
| --- | --- | --- |
| **时间数** | Q | 撑到时间到，Boss 出现，击败它 |
| **杀敌数** | W | 累计击杀达标后 Boss 出现 |

v1.1 只有「杀敌数」一种（累计 40 只引出狼王）。

> 我们现在也只有杀敌数（40 只）。加一个「时间数」几乎零成本 ——
> `maybeSpawnAlpha()` 的触发条件从 `kills >= 40` 换成 `day >= N` 即可，
> 而它带来的是一种完全不同的玩法取向：**苟活流 vs 猎杀流**。

### 3.3 水分 / 饥饿的钳位与预警（v1.1 没有）

v1.4 新增了这些 `PlayerState` 事件：

| 触发器 | 条件 | 作用 |
| --- | --- | --- |
| `008` / `008_u` | 水分 > 100 / 饥饿 > 100 | 压回上限 |
| `008________2` / `008______________u` | 水分 < 0 / 饥饿 < 0 | 抬回 0 |
| `_____________0_u` | **水分 < 6** | 低值预警 |
| `________________0_0` | **饥饿 < 8** | 低值预警 |

v1.1 只有「≤0 即死」这一条，没有钳位也没有预警。
这说明 1.1 → 1.4 之间作者收到的反馈里，**"死得莫名其妙"是个真问题** —— 和我们这边遇到的一样。

### 3.4 新的一个 400 秒周期触发器

`Trig________________u` 每 **400 秒**触发一次。400 正好是 v1.1 里火窖的燃烧时长
（100 HP / −0.25 HP/s）。用途待查，但周期与火窖寿命吻合，可能是某种全局补给或事件节拍。

### 3.5 内容扩充（不影响机制）

- **武器星级从 2 档扩到 3 档**：`☆` / `☆☆` / `★`（v1.1 只有 ☆ 和 ★）
- **VIP 系统**：`Svip光环`、`Svip宝贝`、`Vip斗篷`
- **多人快捷喊话**：「跟着我来！」「形势很紧急。」「收到，了解。」等一组固定短语
- **丧尸**（新敌人名，与已有的「生化僵尸」并存）
- 模型从 29 个涨到 74 个

## 4. 对我们的行动建议

按性价比排序：

**① 抄难度的实现思路（高价值、低成本）**
不要复制四套刷怪表。给 `getNightScaling()` 加一个难度系数即可：

```
简单 ×0.7 / 普通 ×1.0 / 困难 ×1.3 / 挑战 ×1.6
```

再叠加 v1.1 那条「代谢翻倍」的手法，就有了两个正交的难度旋钮。

**② 加「时间数」胜利条件（低成本）**
`maybeSpawnAlpha()` 的门槛从固定的 40 杀改成可配置，另开一档按天数触发。
苟活流和猎杀流是两种玩家，成本却几乎为零。

**③ 低值预警（我们已经做了一部分）**
v1.4 在水分<6、饥饿<8 加预警，说明这是被玩家反馈推出来的。
我们的 HUD 已有 `WATER_URGENT = 32` 的交互抢占，但**饥饿没有对应的预警**，可以补。

**④ 不建议抄的**
VIP 系统、多人喊话、3 档武器星级 —— 都是长局多人 RPG 的配套，
我们是单人短局，抄过来只会摊薄。

## 5. 解密说明（复现用）

```bash
python _tools/dump14.py
```

v1.4 保留了 `(listfile)`，所以比 v1.1 好处理得多 —— 不需要靠"扇区偏移表第一项等于表长"
去反推密钥。但仍然逐文件加密，`_tools/w3x14.py` 里的密钥推导和补齐 mpyq 丢失尾字节的修正照旧需要。

**未解出的 22 个块**是音频，用了 huffman(0x01) + adpcm(0x40) 混合压缩，
我们的脚本只实现了 zlib 和 bzip2。数值分析用不到，没有补。

**编码**：v1.4 的 `war3map.wts` 带 UTF-8 BOM，读的时候要用 `utf-8-sig`，
否则第一条字符串会多出一个 `\ufeff`。
