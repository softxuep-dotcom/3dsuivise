## 1. Poki playtest 那张表怎么读（这一节最要紧）

### Duration 不是单局时长

**Duration = 这一次会话的总停留时间；Plays = 这次会话里 `gameplayStart` 被调了几次。**

所以按 Duration 排序，排的是「谁最舍不得关页面」，而**重开一次就刷新一次计时** ——
这张表在结构上就会把反复重开的人顶到最上面。

想看单局，得算 `Duration / Plays`。

### Plays 曾经被开背包污染

`isGameplayBlocked()` 里含 `inventoryOpen`，而它同时驱动平台上报，于是
**每开一次背包 = 一次 `gameplayStop` + 一次 `gameplayStart` = Plays +1**。

背包是吃饭、烤肉、合成、建造的唯一入口，**玩家活得越久开得越多**——
也就是说这个 bug 专门惩罚你最想要的那批人：

```
德国  03:33 / 3 plays   被记成 3 段，平均 71 秒（真实 213 秒）
印度  05:50 / 8 plays   被记成 8 段，平均 44 秒（真实 350 秒）
```

Fit Test 的过线是平均 3 分钟。那个德国玩家真实 213 秒**是过线的**，
被切成 71 秒之后反倒成了拉低平均分的样本。

**这条已经修了**（`01af8fc`，把 `f81b160` cherry-pick 回来）。但注意：

- 修复曾经存在于 1.0.29，被 `6172790`「完全回退到 1.0.28」**顺手带走** ——
  那次回退针对的是镜头和剔除值，四个提交打包扔的。同批的韩文动词修复
  后来单独补回来了（`d0ea133`），只有这个漏了一个月。
- **2026-08-22 之前采集的所有 playtest 数据都带这个污染**，而且是均匀污染：
  跨版本比 Plays 还算公平，但任何一条的绝对值都不能读。

### 不能用 `Plays = 1` 筛「干净单局」

我在这上面栽过。`Plays = 1` 意味着这个人**从没开过背包**，
而背包只有活得久的人才开得了 —— 等于先把活得久的人删掉，再宣布没人活得久。

我据此报过「没有一个真实玩家越过 190 秒黎明」，**那个结论不成立，没验过**。
恰恰被剔掉的两条（德国 213s / 3 plays、印度 350s / 8 plays）才是最可能过夜的。

### 投放波次：判断记录来源的硬指标

Poki 把测试推给它的受众是**几分钟内的一次爆发**，各国手机记录密集涌入。
波次之外的记录来源可疑。46 条那批的形状：

```
22 Aug  05:54–05:58   14 条，14 个国家，几乎全是手机   ← 投放波
        06:50 (+52m)  CN 19:14 / 24 plays / 桌面
        07:14 (+76m)  CN 37:05 / 39 plays / 桌面

21 Aug  01:52–01:57    9 条                            ← 投放波
        02:24 (+27m)  CN 20:31 / 32 plays

18 Aug  23:01–23:06    6 条                            ← 投放波
        23:18 (+12m)  CN 13:51 / 13 plays
```

四条 CN 长记录**全部落在波次结束之后**，四个批次一次不落，每传一个新包就多一条。
而落在波次**里面**的两条 CN 记录是 `00:26 / 1 play` 和 `01:48 / 2 plays` ——
跟德国、印度、土耳其混在一起挑不出来。

**真正的中国玩家一点都不特别。** 至于波次外那四条到底是谁，
Actions 列的 ▶ 是会话录像，点开看比任何推理都硬 —— 这一步还没做。

## 2. 语言侧查过什么（三处干净，别重查）

| 面 | 方法 | 结论 |
|---|---|---|
| 四颗圆键标签 | 手机视口 375px 的真页面里，把 21 个键（`action.*` / `thermal.*` / `hud.*.label`）逐条塞进 `#action-label` 和 `#thermal-state`，占位符替换成真值，量 `scrollHeight > clientHeight` | **12 语种零截断**。约束是 `8px` 字号 / `max-width: 62px` / `-webkit-line-clamp: 2` |
| 翻译完整度 | 401 个键逐条比对英文，找逐字相同且「像散文」（含空格 + 拉丁字母 + 长度 > 6）的条目 | **无漏翻**。对上的全是 `{name} ×{count}`、`{left} + {right}` 这类纯格式串，加 "Machete I/II/III"（德西意葡同词）和游戏名 |
| 目标行版面 | 手机上 `.left-stack` 只有 `min(300px, 38vw)` = 142px，实测各语种渲染高度与横向溢出 | **不裁切不溢出**。德/西/俄 6 行 vs 中/日 4 行（113px vs 83px），但左列下面只有时钟和设置键，没有被顶掉的东西 |

**别再按字符数估圆键宽度** —— `styles.css` 里已有的注释是对的：字符最长的是德/意/法，
但像素最宽的常是俄语（西里尔单字更宽）。

## 3. 字幕时长：已修的那条

六处 `showToast` 各挂一个常数（message 3.1 秒、昼夜 3.4、拾取 1.4、猎杀 1.8、
发车 5、缺省 2.3）。**这些数字全是对着中文调的**，而中文是十二种语言里最短的：

```
zh  5102 字    ja  6067    ko  7601    tr 11944    en 12148
vi 12705       ru 13508    pt 13602    es 13612    it 13781
de 13728       fr 14179                        （各 402 个键合计）
```

法文是中文的 **2.78 倍**。

### 关键：要把「注意到字幕」的开销算进去

字幕不在视线焦点上（玩家正盯着人物和狗），每条都要先付一次注意的钱，按 1.2 秒计。
付完之后 3.1 秒里**只剩 1.9 秒能读字**。这一笔算不算，结论完全不同：

```
不算注意开销   zh 19.9%  en 18.1%  fr 25.1%   → 看起来「中文没优势」
算上注意开销   zh 31.1%  en 40.6%  fr 43.6%   → 中文比法文低 12.5 个点
```

**我第一次算漏了这一笔，报了「中文字短这条基本不成立」，那是错的。**
真实情况是两件事同时成立：

1. 中文确实占便宜，差 12.5 个百分点；
2. **3.1 秒对谁都不够** —— 源语言自己也有三成读不完。

改法见 `src/ui/ToastDuration.ts`（`31fdae2`）：分脚本计速（汉字假名 7 字/秒、
谚文 9、拉丁西里尔 16 字符/秒）+ 1.2 秒注意开销 + 6 秒上限，
只接在 `showToast` 开头一处，六个调用点的数字一个没动。

## 4. 没修的：`msg.1`，玩家看到的第一句话

模拟层探针跑开局 40 秒，**只有 2 条字幕**。第一条是 `msg.1`，在新算法下**仍然读不完**：

```
de     106字符  需 7.8s  挂 6.0s  ← 差 1.8s
pt-BR   95字符  需 7.1s          ← 差 1.1s
es/fr   92字符  需 7.0s          ← 差 1.0s
it      88字符  需 6.7s          ← 差 0.7s
vi/en/ru        需 6.1~6.4s      ← 差 0.1~0.4s
────────────────────────────────
zh      22字符  需 4.1s  ✓    ja / ko / tr  ✓
```

**十二种语言里八种看不完第一句话。**

根因不是翻译，是这一句塞了**两条指令**：「首次移动后开始计时」+「天黑前添柴并封住入口」。
中文 22 个字装得下，德文要 106 个字符。

卡住它的是 6 秒上限，而那个上限的职责是**防止长文案饿死后面排队的指令**——
可 `msg.1` 在 t=0 出现时队列是空的，它谁也没饿着。

**建议改法：上限只在队列非空时生效。** 改 `showToast` 一处，`toastSeconds` 加一个参数。

不推荐的两条：把上限抬到 8 秒会和 `TOAST_STALE_SECONDS = 6` 打架（后面排队的普通提示
会成批过期）；把 `msg.1` 拆成两条最干净，但要动 12 个语言文件和内容设计。

## 5. 「为什么中国数据高」四条假设的判定

| # | 假设 | 判定 |
|---|---|---|
| 1 | 中文字偏短，适合阅读 | **部分成立**，31.1% vs 43.6%，差 12.5 个点。已修 |
| 2 | 中文是源语言，文本语境更优 | **成立，最实**。见下 |
| 3 | 中国人喜欢这类游戏 | **成立但数据验不了**。见下 |
| 4 | 中国人习惯玩游戏看字 | **成立**，且与第 1 条扣合 |

**第 2 条**不是长度问题，是**只有中文被作者本人校对过**。硬证据是 `d0ea133`：
韩文 `action.chop`（砍树枝）挂着「劈柴」、`action.cactus`（割仙人掌）挂着「砍伐」——
392 个键一个不缺，翻译全在，但动词和按下去干的事对不上。那条提交信息里还写着更深一层：
「中日都选了说结果而不是说动作（取汁 / 发车），韩文三条全在说动作」——
**中文定的是修辞策略，翻译只搬字面**。而韩文那条是碰巧撞见的，
剩下十种语言 × 400 个键没有人校对过。

**第 3 条**：这个游戏是《荒漠幸存者》的复刻（见 `docs/荒漠幸存者-数值分析.md`，
173 个数据块追到 `war3map.j`）。那是魔兽 RPG 老地图，中国有一整代人玩过，
英文同族 *Wilderness Survival* 体量差着数量级。四条生存轴、篝火添柴、怪物寻火、
夜里攻营 —— 老玩家一进去就知道那 40 秒该干什么，**而「不知道那 40 秒该干什么」
正是 `游戏测试-交接.md` §0 认定的死因**。

**第 4 条**：第 1 条量出的那批读不完是全语种共有的。读不完的时候谁会停下来读完？
愿意读字的人。Poki 的受众主力是巴西 / 印度 / 印尼 / 菲律宾的手机玩家，
对文本的容忍度是全网最低那一档。所以机制不是「中国人读得快」（量出来不是），
是**「中国人愿意读」**，而这个游戏在开局 40 秒里要求玩家读字。

## 6. 测量陷阱（都是这一轮踩出来的）

1. **`git diff --stat` 会显示 CRLF 归一化造成的幻影改动**，跟 `git status` 打架时以
   `git status` 为准。我据此误报过「工作区还压着抓狼扔狼那一摊」，
   而那个功能早在 `81d32eb` 就提交了。
2. **浏览器面板量 CSS 要先切到手机视口**。桌面断点下圆键标签是 `13px / 128px`，
   手机断点才是 `8px / 62px` —— 而 playtest 流量几乎全是手机。量错断点会全绿。
3. **量文案宽度必须替换占位符**。`"Nhiệt độ {seconds} giây"` 字面量会超框，
   实际渲染时 `{seconds}` 是个 1~2 位数字，不超。
4. **阅读时间模型必须含「注意到」的固定开销**，否则跨语言差距会被系统性低估（见 §3）。
5. `tests/tmp/` 是临时探针的位置（`.gitignore` 覆盖），`tests/tmpprobe/` **不**被忽略。
   跑探针要加 `--disable-console-intercept`，否则 `console.log` 被 vitest 吞掉。
6. 探针里 `createWorld` 在 `src/game/content/createWorld`，不在 `simulation/` 下。
