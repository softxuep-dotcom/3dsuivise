> 版本：v4 · 2026-08-12
> 沿革：v1 两阶 → v2 补三阶与材料 → v3 取消长柄、统一冷却、刃形与颜色区分 → v3.1 保留无上限横扫、群体轴改由扇形承担 → **v4 修正「刀强于剑」的设计缺陷（剑线签名换成连击、劳力拉平），补齐升级 UI 与落地计划**。

## 0. 三条硬约束

设计空间是被下面三条**先**框死的，所有数值都是在框里解出来的。

### 0.1 只有一个可用的攻击动画

`Rig_Medium_CombatMelee.glb` 里保留了两个 clip（[optimize_kaykit_player.mjs:24](authoring/assets/optimize_kaykit_player.mjs:24)）：`Melee_1H_Attack_Chop`（单手劈砍）与 `Melee_2H_Attack_Stab`（双手突刺）。

全线改成**刀与剑**之后，Stab 用不上，**六把武器共用一个劈砍动作**。

> **顺带修一个现存 bug**：[GameRenderer.ts:1285](src/render/GameRenderer.ts:1285) 是 `weapon === "iron-spear" ? Stab : Chop`，三阶的 `fang-spear` 落进 else 分支，拿着重矛播匕首的劈砍。v4 全用同一个 clip，这个 bug 自然消失。

### 0.2 攻击冷却全线统一 0.55 秒

代价是**攻速这条轴没了**。好处是一个动画配一个固定节奏，不会出现"动画播完了还在冷却"的错位（时间缩放是 `clip.duration / 0.22`，[GameRenderer.ts:1287](src/render/GameRenderer.ts:1287)）。

### 0.3 命中数量无上限（保留现状）

`requestAttack()` 对射程内的全部目标逐个结算，**这条不改**。群体能力全部由**扇形角 × 攻程**决定，也就是命中面积。

## 1. v4 修正了什么：刀曾经强于剑

v3.1 的分化是「刀＝大面积，剑＝高单击」。摊开看，剑只有两个优势，刀有四个：

| | 刀三（v3.1） | 剑三（v3.1） | |
| --- | ---: | ---: | --- |
| 单体 DPS | 104.5 | **138.9** | 剑 +33% |
| 命中面积 | **35.3 m²** | 11.1 m² | 刀 3.18× |
| 劳力/目标（被围时） | **1.5** | 7 | 刀 4.7× |
| 破甲 | **8** | 0 | 刀 |
| 击退减伤 | **有** | 无 | 刀 |
| 移速 | 0.92 | **1.06** | 剑 |

而那 +33% 只在"面前恰好一个目标"时兑现 —— 全局只有头狼那一场。**一场仗撑不起一条三阶线。**

**根因**：无上限横扫下，面积是**所有**输出的乘数，单击伤害只是**一个**目标的乘数。3.18 倍面积不可能靠 +33% 单击补回来。光调数值调不出来 —— 剑需要一个**不随目标数增长的机制**。

### 1.1 两处修正

| 项 | v3.1 | v4 | 为什么 |
| --- | --- | --- | --- |
| 剑线签名 | 处决（残血目标乘伤害） | **连击（连续命中同一目标逐段加伤）** | 刀每一刀都换目标，结构上永远停在 0 段 —— 这是刀吃不到的机制 |
| 劳力/击 | 刀 4/5/6、剑 5/6/7 | **两条线拉平 5/6/7** | 刀一次打好几个还收费更低，等于白送 |

「处决」删掉不留 —— 它和连击都在奖励单体，留一个就够。

## 2. 四条线的性格

初始的 **求生匕首 / 粗布衣** 是阶 0，不属于任何线。**一阶就分叉。**

| | 铁线 | 轻线 |
| --- | --- | --- |
| 武器 | **刀线（阔刃）**：一刀扫过身周一大圈、破甲、击退打断、移速惩罚 | **剑线（细刃）**：只够到身前一小片，但咬住一个目标越打越疼、高重创、移速加成 |
| 护甲 | **铁甲线**：高防御 + 近战反伤，移速与劳力回复双惩罚 | **皮甲线**：低防御 + 闪避，移速与劳力回复双加成 |
| 主料 | **铁矿**（全图 28~42 块，不再生） | **枯木**（全图约 53 根，不再生，**同时是唯一燃料**） |
| 三阶门槛 | **狼牙**（只从白天的大狼掉） | 同左 |
| 篝火 | 6 个配方全部需火 | 6 个里有 2 个随身可造 |
| 一句话 | **敌人越多越强** | **敌人越少越强** |

| 组合 | 玩法 | 为什么成立 |
| --- | --- | --- |
| 刀 + 铁甲 | **守营流** | 280° 扫一圈 + 防 18 + 击退，站着不动收割夜袭 |
| 剑 + 皮甲 | **游猎流** | 满层 228 DPS 单体秒杀 + 移速 ×1.15，白天扫荡地图 |
| 刀 + 皮甲 | 游击清场 | 清得动群但脆，打了就跑 |
| 剑 + 铁甲 | 站桩处决 | 扛住围殴慢慢点杀，反伤补足清场短板 |

## 3. 攻击系统

### 3.1 分化的八条轴

| 轴 | 刀线 | 剑线 | 要新动画吗 |
| --- | --- | --- | --- |
| 每击伤害 | 低 | **高** | 否 |
| **扇形角** | **220° → 280°** | 100° → 110° | 否，只是 `dot()` 阈值 |
| 攻程 | 3.4 → 3.8 | 3.2 → 3.4 | 否 |
| **↳ 命中面积** | **22.2 → 35.3 m²** | 8.9 → 11.1 m² | — |
| 劳力/击 | 5/6/7 | 5/6/7（拉平） | 否 |
| 破甲 | **2 → 8** | 0 | 否 |
| 重创 | 无 → 15%×2.0 | **20%×1.8 → 40%×2.2** | 否 |
| 移速 | ×0.98 → ×0.92 | ×1.00 → **×1.06** | 否 |
| **签名** | **击退打断** | **连击** | 否 |

### 3.2 攻击循环只改一处

命中数量无上限**原样保留**，狼和猎物仍各走各的循环，不用合并排序。唯一要改的是扇形写死了：`dot(facing, toward) < -0.15` 等价于固定 197°，改成读武器的 `arcDot`。

| 扇形角 | dot 阈值 | 用在 | 命中面积 |
| ---: | ---: | --- | ---: |
| 100° | **+0.643** | 剑一（3.2）/ 剑二（3.3） | 8.9 / 9.5 m² |
| 110° | **+0.574** | 剑三（3.4） | 11.1 m² |
| 160° | **+0.174** | 求生匕首（3.1） | 13.4 m² |
| **197°（现状）** | **−0.148** | — | 16.5~30.3 m² |
| 220° | **−0.342** | 刀一（3.4） | 22.2 m² |
| 250° | **−0.574** | 刀二（3.6） | 28.3 m² |
| 280° | **−0.766** | 刀三（3.8） | 35.3 m² |

> 面积 = `(扇形角 / 360) × π × 攻程²`

**剑线要瞄。** 100° 意味着背后和侧后完全砍不到 —— 这是"精准"在操作层面唯一能落地的地方。**刀线 280° 只剩正背后一个 80° 的死角**，被围时基本不用管朝向。

### 3.3 刀线签名：击退打断

命中时把目标沿"你 → 它"方向推开，**并把它的 `attackCooldown` 往后推**。

| 阶 | 推开 | 咬击延后 |
| --- | ---: | ---: |
| 刀一 | 0.35 m | +0.20 s |
| 刀二 | 0.50 m | +0.30 s |
| 刀三 | 0.70 m | +0.40 s |

真正值钱的是**延后**那一列。狼移速 3~5 m/s，0.7 米两百毫秒就走回来了；但狼的咬击间隔是 1.15 秒（[GameSimulation.ts:1461](src/game/simulation/GameSimulation.ts:1461)），你每 0.55 秒给它 +0.4 秒，等于**把它的输出压掉七成**。乘上"同时打五六只"，这就是刀线守夜能力的真正来源 —— 不在伤害上，在减伤上。

- **头狼免疫击退**（否则 BOSS 战变推箱子）。
- 推开要走 `stepAxis()` 的可行走检查，推不动时放弃位移、只保留咬击延后。

### 3.4 剑线签名：连击

**连续命中同一目标**逐段加伤；换目标、或 1.2 秒没有命中，立即清零。

| 阶 | 每段 | 上限 | 满层 |
| --- | ---: | ---: | ---: |
| 剑一 骨柄短剑 | +10% | 3 段 | +30% |
| 剑二 兽牙细剑 | +12% | 4 段 | +48% |
| 剑三 裂齿长剑 | +15% | 4 段 | **+60%** |

关键在于**刀结构上吃不到这个机制** —— 它每一刀都同时砍好几只，目标一直在换，永远停在 0 段。这是唯一一条"用得越专一越强"的轴，和刀线"用得越杂越强"正好互为反面。

状态只有三个字段：`comboTargetId` / `comboStacks` / `comboTimer`。剑线单目标命中时推进，刀线不写入。

### 3.5 伤害结算顺序

```
每击伤害 = max(1,
  round(武器攻击力 × 重创倍率 × 连击倍率 × 需求系数 × 劳力系数)
  − max(0, 目标护甲 − 破甲)
)
```

**倍率全部在减护甲之前结算** —— 让倍率对"打有甲目标"格外划算。`需求系数`（饥渴 <15 时 ×0.8）与 `劳力系数`（脱力 ×0.6）沿用现状。

### 4.1 DPS 验算

重创期望倍率 `E = 1 + p(m−1)`；`E_hit = 攻击 × E`；剑线再乘连击层数倍率。

| | 刀一 | 刀二 | 刀三 | 剑一 | 剑二 | 剑三 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 重创期望 E | 1.000 | 1.096 | 1.150 | 1.160 | 1.300 | 1.480 |
| E_hit（0 段） | 34.0 | 46.0 | 57.5 | 44.1 | 58.5 | 81.4 |
| E_hit（满层） | — | — | — | **57.3** | **86.6** | **130.2** |

**单体 DPS**（÷0.55）：

| 目标护甲 | 匕首 | 刀一 | 刀二 | 刀三 | 剑一满层 | 剑二满层 | 剑三满层 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0（猎物） | 54.5 | 61.8 | 83.6 | 104.5 | 104.2 | 157.5 | **236.7** |
| 5（大狼） | 45.5 | 56.4 | 83.6 | 104.5 | 95.1 | 148.4 | **227.6** |
| 9（头狼） | 38.2 | 49.1 | 76.4 | 102.7 | 87.8 | 141.1 | **220.4** |

**被围**（6 只均匀分布在四周）。刀三扫到 280/360 = 77.8% = 4.67 只，剑三只扫到 110/360 = 30.6% = 1.83 只，且目标一直在换、**连击永远起不来**：

| | 刀三 | 剑三 | |
| --- | ---: | ---: | --- |
| 每挥总伤害（护甲 5） | 52.5 × 4.67 = **245** | 76.4 × 1.83 = 140 | **刀 1.75×** |

**满劳力（100 点）总伤害**（护甲 5）—— 夜里回不了劳力，这才是真上限：

| | 刀一 | 刀二 | 刀三 | 剑一 | 剑二 | 剑三 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 可挥次数 | 20 | 16.7 | 14.3 | 20 | 16.7 | 14.3 |

- **单体持久战**：剑三 **2.38×** 刀三
- **被围**：刀三 **1.75×** 剑三

> 劳力口径：挖矿 15/块、捡枯木 30/根（[GameSimulation.ts:217](src/game/simulation/GameSimulation.ts:217)、[:224](src/game/simulation/GameSimulation.ts:224)）。

四条路的采集劳力刻意做到 375~390，几乎相等。区别不在"花多少力气"，在**花在哪个池子里**：

- **铁线抽干的是一个死池子。** 全图 14 个矿点 × 2~3 块 = 28~42 块，不再生，且没有第二个用途。双铁线吃掉全图一半到四分之三。
- **轻线抽的是你的火。** 枯木全图约 53 根，**同时是唯一燃料**（1 根 = 篝火 +95 秒）。四个夜晚合计 690 秒，维持一堆火最少 8 根。双轻线要 13 根 —— **拿今晚的火换明天的剑**。何况随身枯木还给 +2 攻击（上限 2 根）。
- **兽皮和狼牙都要出门打狼。** 白天野狼同时存活上限 5 只、每 9 秒补一只（[GameSimulation.ts:1908](src/game/simulation/GameSimulation.ts:1908)）；小狼掉 1 张皮、大狼掉 2 张。

| 项 | 值 |

| 来源 | **只有白天的大狼**掉落，1 颗/只（夜袭狼依旧什么都不掉） |

## 6. 护甲数值表

- **闪避**：命中判定前掷骰，闪掉整次咬击（伤害 0，但仍触发受击表现与"挨打后 6 秒不能休息"的锁）。

- **劳力回复**：乘在 `STAMINA_REST_REGEN / IDLE / ACTIVE` 三档上（[GameSimulation.ts:212](src/game/simulation/GameSimulation.ts:212)）。
- **护甲不影响体温** —— 沿用 `docs/survival-systems.md` §0.3 的既有决策。

### 6.1 挨打验算：两条线在哪里交叉

第 5 天狼的原始攻击：小狼 22、大狼 28、头狼 38。每次咬击的**期望承伤**：

| 护甲 | 小狼 22 | 大狼 28 | 头狼 38 |
| --- | ---: | ---: | ---: |
| 粗布衣（防 2） | 20 | 26 | 36 |
| 铁一（防 8） | 14 | 20 | 30 |
| 皮一（防 5 · 闪 12%） | 15.0 | 20.2 | 29.0 |
| 铁二（防 13） | 9 | 15 | 25 |
| 皮二（防 6 · 闪 24%） | 12.2 | 16.7 | 24.3 |
| 铁三（防 18） | **4** | **10** | 20 |
| 皮三（防 7 · 闪 38%） | 9.3 | 13.0 | **19.2** |

解交叉点 `A − D铁 = (A − D皮)(1 − 闪避)`：一阶 **30.0**、二阶 **35.2**、三阶 **35.9**。

第 5 夜头狼 38 过线，大狼要到第 8 夜（37）才过。**重甲是守夜的甲，皮甲是打头狼的甲。** 减法防御吃"多而弱"，百分比闪避吃"少而重" —— 这是公式本身的形状。

### 6.2 移速与劳力的复利

| 组合 | 系数 | 实际移速（基础 8.2） | 第 5 夜最快的狼 |
| --- | ---: | ---: | ---: |
| 熔渣重刀 + 熔渣板甲 | 0.92 × 0.88 = 0.810 | **6.64** | 5.1 |
| 裂齿长剑 + 狼影斗篷 | 1.06 × 1.09 = 1.155 | **9.47** | 5.1 |

差 43%，但重装依然跑得过狼（第 8 夜最快 5.63 也追不上 6.64）。**慢是税，不是死刑。**

劳力回复（180 秒白天全程移动，基础 1.1/s = 198 点）：铁三甲 ×0.85 → 168；皮三甲 ×1.35 → 267。差出来的 99 点 ≈ **6.6 次挖矿** 或 **3.3 根枯木**。

## 7. 视觉区分：刃形 + 颜色

刀是程序化的（[GameRenderer.ts:1109](src/render/GameRenderer.ts:1109)），刃身是一个五点 `Shape` 挤出来的：

## 8. 升级 UI 设计

### 8.1 现状与要解决的问题

升级入口在背包浮层里（`.craft-list`，一个 `1fr 1fr` 的按钮网格，[styles.css:668](src/styles.css:668)），**打开背包会暂停游戏** —— 这一点很关键，意味着分叉决策可以在静止状态下从容做，不需要担心信息量。

现在只有两个按钮，`syncUpgradeButton()` 渲染"这条线的下一阶"（[HudController.ts:423](src/ui/HudController.ts:423)）。分叉之后要解决三件事：

1. 阶 0 时每个槽位有**两个候选**，而且要在按下之前就让玩家看懂两条线的差别；
2. 分叉之后要收回单一入口，并且**能看出自己在第几阶**；
3. 换线要能做，但不能手滑做成。

### 8.2 三种状态

升级区在任意时刻只有三种状态，按当前装备的 `line` 与 `tier` 决定：

| 状态 | 条件 | 呈现 |
| --- | --- | --- |
| **A 分叉卡** | `tier === 0` | 两栏对比卡 |
| **B 升级卡** | `0 < tier < 3` | 单张卡 + 折叠的换线入口 |
| **C 满级卡** | `tier === 3` | 属性总览 + 折叠的换线入口 |

### 8.3 状态 A：分叉卡

**不能是两个并排的按钮。** 按钮只有一行字的预算，而这是全局最重的一次决策 —— 它决定接下来四天的采集路线。所以用对比卡：

```
┌───────────────────── 武器 · 选一条线 ─────────────────────┐
│ ▎刀 · 阔刃              ▎剑 · 细刃                        │
│ ▉▉▉ 冷钢蓝              ▉▉▉ 骨白                          │
│                                                           │
│ 敌人越多越强            敌人越少越强                       │
│ 一刀扫过身周一大圈      咬住一个目标越打越疼               │
│                                                           │
│ 铁片砍刀                骨柄短剑                           │
│ 扇形 220° · 攻击 34     扇形 100° · 攻击 38               │
│ 破甲 2 · 击退           连击 +10%×3                        │
│                                                           │
│ 铁矿 2/3 ✗ 兽皮 1/1 ✓   兽皮 1/1 ✓ 枯木 0/2 ✗            │
│ ⚠ 需燃烧篝火            ✓ 随身可造                         │
│                                                           │
│ ●○○ 终点 熔渣重刀       ●○○ 终点 裂齿长剑                 │
│ [ 还差 铁矿×1 ]         [ 还差 枯木×2 ]                    │
└───────────────────────────────────────────────────────────┘
```

每一栏从上到下回答五个问题，顺序不能换：

| 行 | 回答的问题 | 为什么在这个位置 |
| --- | --- | --- |
| 色条 + 线名 | 这是哪条线 | 颜色和世界里的刀刃一致，建立对应关系 |
| **性格两行** | **它擅长什么** | 最重要的信息放最高，且**先说抽象性格再说具体武器** —— 玩家要选的是"线"不是"这把刀" |
| 一阶名 + 属性 | 我现在能拿到什么 | — |
| 配方 + 站点 | 我够不够、要不要回营地 | 站点单独一行，因为"随身可造"是轻线最大的早期优势 |
| 阶数点 + 终点名 | 这条路通向哪 | 让玩家知道自己在承诺一条**三阶的路**，不是一件装备 |

`⚠ 需燃烧篝火` 在不在火边会变：不在火边显示 `⚠ 需燃烧篝火（当前不在火边）`，在火边显示 `✓ 篝火就在旁边`。这条现在也有（`syncUpgradeButton` 拼的 `fire` 后缀），只是没做状态区分。

**响应式**：桌面两栏并排（`grid-template-columns: 1fr 1fr`）。触屏档（`@media (pointer: coarse), (max-width: 760px)`）改成上下堆叠 `1fr`，并把"性格两行"压成一行 —— 背包卡在触屏只有 `min(620px, 86vw)` 宽度预算（[styles.css:850](src/styles.css:850)）。

### 8.4 状态 B：升级卡

```
┌─ 武器 · 刀线  ●●○ ───────────────────────────┐
│ 当前  锻铁阔刀   扇形 250° 攻击 42 破甲 5     │
│   ↓                                           │
│ 下阶  熔渣重刀   扇形 280° 攻击 50 破甲 8     │
│                                               │
│ 铁矿 5/5 ✓  兽皮 1/2 ✗  狼牙 3/3 ✓            │
│ ⚠ 需燃烧篝火（当前不在火边）                   │
│                                               │
│ [ 还差 兽皮×1 ]                               │
│ ⟲ 改走剑线                                    │
└───────────────────────────────────────────────┘
```

- **当前 → 下阶并排**，属性同列对齐，涨了的数字高亮。现在的按钮只写下一阶的 `blurb`（"攻击+18"），玩家得自己记住原来是多少。
- **阶数点 `●●○`** 放在标题栏。三阶是本设计最大的新增结构，玩家需要一个随时可见的进度。
- **配方逐项打勾**，不满足的标红。现有的 `材料 有/需` 格式保留，只是加符号。
- 按钮文案说**还差什么**，不是"材料不足"。这条现有实现已经做对了，保留。

### 8.5 状态 C：满级卡

```
┌─ 武器 · 刀线  ●●● 已满级 ────────────────────┐
│ 熔渣重刀                                      │
│ 攻击 50 · 扇形 280° · 攻程 3.8 · 破甲 8       │
│ 重创 15%×2.0 · 劳力 7/击 · 移速 −8%           │
│ 击退 0.70m · 咬击延后 +0.40s                  │
│                                               │
│ ⟲ 改走剑线                                    │
└───────────────────────────────────────────────┘
```

满级之后按钮不能只写"武器已满级"（现状如此）—— 那是一块死区。改成属性总览，让玩家知道自己拿的到底是什么。

### 8.6 换线：二次确认

`⟲ 改走剑线` 点第一下**原地变成红色确认条**：

```
⚠ 丢弃熔渣重刀，从骨柄短剑重来。材料不返还。 [ 确认 ]  [ 取消 ]
```

再点"确认"才执行。3 秒无操作自动收回。背包本来就暂停游戏，二次确认不打断节奏。

不用 `window.confirm()` —— 它在触屏上会顶出系统弹窗，且样式失控。

### 8.7 装备栏加色条

`.equipment-row` 的「衣物 / 武器」两格加一条 3px 的左边框，颜色取 §7.2 的刃色/甲色。背包一开就知道自己走的哪条线，**且和世界里看到的武器是同一个颜色**。这是零成本把 §7 的颜色语言接进 UI。

### 8.8 连击指示器（唯一需要动实时 HUD 的地方）

剑线的连击必须在战斗中可见。屏幕中央已经清空（见 `ab1a263` 与 `1476fbc` 两次 HUD 重排），所以挂在**攻击按钮**上 —— 那里本来就是拇指区，符合"所有操作下放到拇指区"的既有方向：

- 攻击按钮外圈加一道 3px 的弧，按层数填充（1/4 … 4/4）
- 满层时弧变成骨白并轻微呼吸
- 配合 §7.3 的刃身自发光：**盯着狼看时靠刃光，需要确认时瞄一眼按钮**

刀线不需要指示器 —— 击退在画面上是自明的（狼被推开）。

### 8.9 首次分叉的教学

阶 0 且材料已够时，`getObjective()` 追加一句：**`开背包选一条武器线 · 刀还是剑`**。分叉卡第一次打开时两栏各闪一次描边，只做一次（存在 `Records` 里，跨局不再提示）。

现在的教学文案硬编码了"粗铁矛"和"兽皮衣"（[GameSimulation.ts:799](src/game/simulation/GameSimulation.ts:799)、[:1138](src/game/simulation/GameSimulation.ts:1138)），必须改成按当前线动态生成 —— 否则拿着骨剑会被提示"3 块铁矿可制作粗铁矛"。

### 8.10 DOM 与代码改动

| 项 | 改动 |
| --- | --- |
| `index.html` | `craft-coat-button` / `craft-spear-button` 两个 `<button>` → 两个 `<div class="upgrade-slot" data-line="weapon|armor">` 容器，内容由 JS 渲染 |
| `styles.css` | 新增 `.fork-card` / `.upgrade-card` / `.tier-pips` / `.confirm-bar` / `.line-swatch`；`.craft-list` 保留给烤肉、洗脸水、树桩 |

`getUpgradeOptions()` 返回候选数组而不是单个，是这套 UI 的**唯一接口改动** —— 三种状态都能从这一个函数的返回值推出来（长度 2 = 分叉，长度 1 = 可升级，长度 0 = 满级）。

## 9. 分叉与换线规则

- **阶 0 → 一阶**：四条线的一阶同时可造，谁先满足材料谁先造。
- **一阶 → 二阶 → 三阶**：**只能升同线**。
- **换线**：随时可造另一条线的**一阶**，材料**不返还**，且从一阶重新爬（§8.6 二次确认）。

**真正的硬约束不在规则里，在材料池里**：双铁线吃掉全图 50~75% 的铁矿，你没有余量在同一局里再爬一遍另一条铁线。**稀缺性做锁，比规则做锁更好。**

## 11.5 实测验收（P0–P8 全部落地后）

无头模拟层跑分器逐项复现设计表。**实测值系统性比设计值低 3~5%**，原因是台架每帧调一次
`requestAttack()`，而冷却 0.55 秒在 1/60 的步长上要 34 帧才归零（0.567 秒），
不是 33 帧 —— 这是采样方式的偏差，不是实现的偏差。

### 单体 DPS（20 秒，劳力锁满）

| 武器 | 护甲 0 | 护甲 5 | 护甲 9 |
| --- | ---: | ---: | ---: |

| 铁片砍刀 | 59.5 | 54.3 | 47.3 |
| 锻铁阔刀 | 80.3 | **80.3** | 73.3 |
| 熔渣重刀 | 97.5 | **97.5** | **95.8** |

| 兽牙细剑 | 127.7 | 118.9 | 111.9 |

### 台架本身踩到的两个坑

1. **`update()` 有一道 `if (!this.clockStarted) return;`** —— 玩家没动过之前整个世界是冻结的。
   全程零输入的台架必须先踢一脚（随便调一次 `requestAttack()`），否则
   `updateWolves` / `updateNeeds` 一帧都不会跑，量出来全是 0。
2. **夜袭狼（`role: "raider"`）只在夜里 hunting**，白天摆在玩家脸上也不会咬。
   量护甲要用 `role: "wild"` + `provoked: true` 的野狼。

- **P3 必须早于 P4**：签名机制要挂在新的伤害公式上。
- **P5.5 必须早于 P6**：否则二阶三阶造出来没地方用。
- **P1 与 P5 完全独立**，随时可插。

## 12. 留给实测的开放项

1. **刀线 280° 会不会太舒服。** 只剩正背后 80° 死角，几乎不用管朝向。若刀线玩家完全不需要走位，三阶收回 250°（面积 31.5 m²，仍是剑三的 2.8 倍）。
2. **剑线 100° 会不会太憋屈。** 猎物常成群（甲壳虫 population 9），窄扇形一次只扫得到一两只；触屏摇杆转向精度不如键鼠，可能老是砍空。若手感差放宽到 130°（`dot ≥ +0.42`，面积 11.6 m²）—— 但面积比会从 3.18 掉到 2.4，分化变弱。**先按 100° 试。**
3. **连击 1.2 秒的窗口。** 冷却 0.55 秒，正常连打是够的，但被打断走位一次就断。若实测层数长期上不去，放宽到 1.8 秒。
4. **击退会不会把狼推出地形。** 必须走 `stepAxis()` 可行走回退，推不动时放弃位移只保留咬击延后 —— 否则狼会卡在崖边抽搐。
5. **闪避的方差。** 38% 闪避整夜样本够，但"头狼最后 20 血"时连续两次没闪掉就是死。若觉得脏，改成**保底**（连续 3 次未闪则必闪）。
6. **反伤是不是纯装饰。** 35% 反弹一夜的总量要实测。若低于玩家自己一分钟的输出，抬到 50% 或改成"反弹并施加短暂减速"。
7. **铁矿坏种子。** 全图最少 28 块，双铁线要 21 块，只剩 7 块余量。若出现"矿挖完了但三阶还差 2 块"的死局，矿点从 14 抬到 16，或 `ore: 2 + rand(2)` 改成 `3 + rand(2)`。
8. **第五种材料会不会爆包。** 8 格背包 + 水/汁/肉/皮/铁/木/牙，理论上刚好。若实测频繁"背包已满"，容量抬到 10。

### 13.2 两个问题

**问题一：三阶可能来不及成型。**

三阶要狼牙，狼牙只从白天大狼掉，大狼占比第 2 天才 31%。而 40 是**累计**门槛。

> **这里不下结论。** 早先版本断言"第 2 夜头狼就到"，那是把"刷出 40 只"错当成"杀掉 40 只" —— 实际第一夜 150 秒里，40 只狼要约 138 次挥砍 ≈ 550 劳力，而整夜劳力预算只有 100 + 1.1×150 ≈ 265，连一半都不够；何况夜 1 三只小狼贴身就是 21 伤/秒，100 血撑 5 秒。第一夜的正解是堵门守火，能杀 8~15 只。
>
> **累计 40 杀究竟落在第几夜，必须跑模拟层量，不能推算。** 这是 P5.5 的第一个待测数据。

**问题二：剑线会把头狼秒了。**

剑三满层对护甲 9 是 220 DPS，第 4 夜头狼 836 血 → **3.8 秒**。现在的血量是照着 85 DPS 的武器调的。

反面说法也有道理：头狼是在 40~90 只狼围着你的时候登场的，剑线没有击退、护甲又薄，**那 3.8 秒的输出窗口本身就要自己创造**。所以真正该量的不是"打完要几秒"，是"实际能打到几秒"。同样列进 P5.5 的待测清单。

### 13.3 三条候选解法

| 解法 | 改动 | 代价 |
| --- | --- | --- |
| **A. 抬门槛** | `ALPHA_KILL_REQUIREMENT` 40 → 由实测决定 | 最小改动，一个常数。但"杀够 N 只"本就不透明，抬高会让中间几夜显得漫长 |
| **B. 加时间闸** | 登场条件加 `day >= 4` | 同样一行。把头狼从"刷怪奖励"变成"日程上的事件"，玩家能预期 |
| **C. 杀头狼不直接通关** | 改成**杀掉头狼 + 活到天亮** | 改动最大，但这是 `docs/survival-systems.md` §0.1 里**已经为生化篇写好的**胜利条件，两个篇章因此统一。且让"击杀头狼"从终点变成高潮，后面还有残局要打 —— 三阶装备正好在这一段发挥 |

**倾向 B + C**：B 保证三阶来得及成型，C 保证成型之后还有仗打。但**先量数据再定**，别照着推算改。
