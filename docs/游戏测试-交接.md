| 录像里看到 | 结论 | 该做什么 |

| 玩家完全没动 | 键鼠玩家不知道怎么操作 | 是我们的问题，改开场提示 |

## 2. 这个游戏怎么测

### 唯一可靠的手段是跑模拟层

`GameSimulation` 是纯计算（寻路、地形、狼群状态机全在里面），可以脱离渲染层整局整夜地跑。**这是这个仓库的既定规矩，也是反复吃亏换来的。**

临时探针写进 `tests/tmpprobe/`，跑完删掉：

```bash
npx vitest run tests/tmpprobe/x.test.ts --reporter=verbose --disable-console-intercept
```

`--disable-console-intercept` 必须加，否则 `console.log` 被 vitest 吞掉。

固定探针放 `tools/`（已有 `probe-world.ts` / `probe-decisions.ts` / `probe-timeline*.ts`）。

### 浏览器面板能做什么、不能做什么

这个环境里浏览器面板**不合成帧** —— `document.hidden` 恒为 true，`requestAnimationFrame` 一帧都不跑。所以：

- ✅ 能验：DOM 结构、CSS 计算值、几何测量（`getBoundingClientRect`）、控制台错误、网络 404、i18n 文案落地
- ❌ 验不了：任何需要帧循环的东西（教学推进、亮洞跟随、动画观感），也**截不了图**

凡是"看起来怎么样"的判断，只能交给用户真机跑一局。写报告时要老实说这一条。

### 关键 API

```ts
sim.update(delta, movement)        // delta 上限 0.05，探针用 1/20
sim.requestAttack()                // 独立入口，只看 running
sim.requestInteraction()           // 同上
sim.drainEvents()                  // 事件是 drain 语义，读完就没了
sim.enableCritters() / enableWolves()   // 生产环境等模型下载完才调，探针里要手动调
sim.start()                        // 不调的话 running=false，update() 直接 return
```

**时钟另有一道闸**：`clockStarted` 要玩家第一次真实移动才置 true，在那之前五轴不掉、相位不走、狼不动。探针里如果发现"跑了 300 秒什么都没发生"，八成是移动向量没过 `0.08` 的阈值。

## 3. 已经测出来的结论（别重新推导）

用户最初的问题是「大部分玩家走一走、挥一下武器就离开」。链条是：

1. **不是无聊，是被咬死。** 中位会话 72 秒，模拟层里不还手的玩家死在 75 秒，97% 掉血来自狗。
2. **开局 40 秒白天里挥刀必定打空** —— 最近可攻击目标 27 米外，一直挥刀的机器人第一次命中在 43.2 秒，即入夜之后 3 秒。玩家学到的是「挥刀没反应」，而那正是 30 秒后救他命的动作。
3. 修法是**世界改动**（出生点 6.3~7.8 米撒教学猎物、6.5 米撒教学枯木），第一次命中 **43.2s → 0.6s**。这个数字跟教学字幕无关。
4. 期间加过一版门禁式开场教学，被平台数据否掉（11 场里 4 场活不过 6 秒），1.0.13 减轻、1.0.14 整段删除。

### 当前瓶颈：第一夜

模拟层实测（1.0.14）：

```
只走不还手        死于  77s
走 + 一直挥刀     死于 100s
绕圈 + 挥刀       死于 127s
缩在营地 + 挥刀    死于 134s   ← 最好的打法

入夜 t=40s，夜袭贴身时刻 42 / 82 / 87 / 124 / 129s，共 5 只
```

而玩家实测最长 117 秒 —— 和模拟层几乎重合。**留存已经从「看不懂」转移到「打不过」。**

一整轮第一昼夜是 40s 白天 + 150s 夜 = 190s，目前没有任何一场走完过。

## 4. 数据怎么读（我在这里栽过）

### 别看中位数，看比例指标

我曾报「中位 20s → 50s」，四场新数据进来就掉回 25s。11 个数的中位数摆动极大。

按当前效应量算，要测出显著需要：

```
≥60s 占比（9% → 33%）    每版约 23 场
≤7s  占比（36% → 7%）    每版约 36 场
现在每版只有 11~15 场
```

**≤7 秒占比是小样本下最稳的指标**，它直接对应「第一眼像不像坏的」。

### 两批已有数据

```
1.0.12  n=11  中位 20s  [3,4,5,6,11,20,30,36,42,52,184]
1.0.14  n=15  中位 25s  [4,8,14,14,18,20,25,25,33,50,60,94,106,110,117]

           ≤7s 秒退   36% → 7%     ← 实打实的好转
           ≥60s 长局   9% → 33%
           中位数     20 → 25s     ← 几乎没动
           8~30s      27% → 47%    ← 中间那段变厚了：不再是打开就跑，但也没走远
```

## 5. 测量陷阱

1. **只看 computed z-index 判断遮挡** —— 数值是 13 > 12，绘制顺序却纹丝不动（`position: fixed` 本身创建层叠上下文）。要用 `document.elementFromPoint` 量真实命中。
2. **用外接矩形量圆按钮的重叠** —— 假阳性。圆按钮按「圆心距 −（半径和）」算。
3. **python 写文件用 `unicode_escape` 解码** —— 把 UTF-8 当 latin-1，中文全乱码，而 i18n 测试只查键集和占位符，查不出来。用字面量 + `encoding="utf-8"`。
4. **共享 `sharedWorld`** —— `GameSimulation` 会就地改动 world，复用会让用例结果取决于前面跑过几条。每条用例现造一个 `createWorld()`。

## 6. 别推翻的决定

| 决定 | 理由 |
|---|---|
| 不要再加门禁式教学 | 试过两版，数据两次否掉。价值在世界改动里，不在字幕里 |
| 幕布必须在 `#hud` 之下 | 层序写死：场景 → 幕布(1) → HUD(2) → 字幕(14) → 遮罩(20/35) |
| UI 高亮用逐元素压暗，不挖洞 | 右下四键彼此只隔 77~89px，照亮一颗的洞会把邻居一起照进去 |
| 捡柴 12 / 砍树 30 的价差 | 表达「这根柴好不好拿」，让玩家先捡光地上的再去砍树 |
| 行动键在拇指位 | 白天攻击不紧急（野狼要被激怒才追），紧急的是捡柴生火；行动键误触无代价，攻击误触扣劳力还惊动狗 |
