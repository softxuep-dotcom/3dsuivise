## 0. 一句话：瓶颈是第一夜，而且模拟层早就把答案算出来了

1.0.14 跑了一轮 **Player Fit Test，n=500，平均时长 2m08s，判定 Fail**。这批数据的量级比之前所有批次（n=11 / n=15）高一个数量级，**以它为准**。

时长直方图（读自图表，±2%）：

```
0–1m  ~148 (30%)
1–2m  ~167 (33%)   ← 最高的一根
2–3m  ~ 92 (18%)
3–4m  ~ 46 ( 9%)
4–5m  ~ 17 ( 3%)
5m+   ~ 39 ( 8%)

活过 1m: 70%   活过 2m: 37%   活过 3m: 19%   活过 5m: 8%
```

**最高的一根不是第一根，是第二根。** 这一条本身就是结论：玩家不再是"打开一看就跑"（那个问题在 1.0.12→1.0.14 已经修掉，≤7s 秒退 36%→7%）。他们进来了、玩起来了，然后在**第 60~140 秒之间集中离开**。

把游戏自己的时钟叠上去，那段时间是什么一目了然：

```
t=  0s   第 1 天白天开始（40 秒）
t= 40s   入夜
t= 46s   第一次挨咬
t= 83s   失温，移速 ×0.25
t= 86~141s   ★ 所有玩家画像在这里死光
t=190s   第一个黎明 —— 没人到得了
```

模拟层实测：**同一画像抖动 6 次，活到 190s 黎明的只有 1 次（17%）。**
平台数据里活过 3 分钟的是 **19%**。两个数字对上了 —— 直方图那根最高的柱子就是第一夜的死亡曲线。

### 该怎么改：把黎明提前

扫过第一夜长度（每档同一画像抖动 6 次，攻击/行动键按固定节奏机械按）：

| 第一夜 | 黎明落在 | 活到黎明 | 整夜贴身次数 |
|---:|---:|---:|---|
| **150s（现状）** | 190s / 3m10s | **1/6** | 3~5 |
| 120s | 160s / 2m40s | 1/6 | 3~4 |
| 110s | 150s / 2m30s | 3/6 | 1~4 |
| **90s** | 130s / 2m10s | **5/6** | 1~4 |

当前中位会话约 1m38s。**夜改 90s 的话黎明落在 2m10s，刚好越过中位玩家的耐心线**；110s 落在 2m30s，是保留夜晚压迫感的折中。

试过但**没用**的（死亡时刻只在噪声里挪动，噪声跨度实测 65s）：

| 改动 | 结果 |
|---|---|
| 失温移速 0.25 → 0.60 | 无变化 |
| 失温攻速惩罚 2.85 → 1.4 | 无变化 |
| 失温**完全不减速** | 仍然全灭 |
| 第一夜攻营 5 → 3 只 | 无变化（甚至更差，是噪声） |

也就是说 **失温不是凶手，狼的数量也不是 —— 是 150 秒太长**。装备为 0、100 点血、一把初始匕首，硬扛 150 秒本来就没有解。

### 顺带量到的第二件事：白天 40 秒够搬一桶油，但游戏不这么说

```
最近的野外油桶  离出生点 32m  离卡车 35m  → 单趟理论 12 秒
卡车            离出生点  8m
```

**理论上第 15 秒就能看到「汽油 1/5」跳一格**，而白天有 40 秒。

但目标行在玩家一迈步就从「加满 5 桶油，开着卡车离开沙海」换成了「走到篝火旁，按互动键添柴」，t=26s 再换成「用入口大石封住缺口」。整个第一昼夜（190 秒）里，通关目标进度**一格都不会动**。

而"囤柴封门"这笔投资是**为第 2 天付的**，可 81% 的玩家根本没有第 2 天。

### 电脑端那个 p=0.007 怎么办

之前挂起的那条（手机中位 77s / 电脑中位 18s，n=15，Fisher p≈0.007）现在有了不花钱的解法：

**Player Fit Test 的建测弹窗里有 Player's device 选项（Any / Desktop / Mobile-Tablet）。**
用**同一个 1.0.14 包**再跑两轮 Desktop 和 Mobile/Tablet，就能拿 n=500 量级的数据替掉 n=7 的推断，而且**不动代码 = 不糊归因**。这件事应该排在任何改动之前做。

## 2. 这个游戏怎么测

### 唯一可靠的手段是跑模拟层

`GameSimulation` 是纯计算（寻路、地形、狼群状态机全在里面），可以脱离渲染层整局整夜地跑。**这是这个仓库的既定规矩，也是反复吃亏换来的。**

临时探针写进 `tests/tmp/`（`.gitignore` 里的 `tmp/` 覆盖到它；`tests/tmpprobe/` **不**被忽略，别用）：

```bash
npx vitest run tests/tmp/x.test.ts --reporter=verbose --disable-console-intercept
```

`--disable-console-intercept` 必须加，否则 `console.log` 被 vitest 吞掉。

固定探针放 `tools/`（已有 `probe-world.ts` / `probe-decisions.ts` / `probe-timeline*.ts`）。

### 浏览器面板能做什么、不能做什么

这个环境里浏览器面板**不合成帧** —— `document.hidden` 恒为 true，`requestAnimationFrame` 一帧都不跑。所以：

- ✅ 能验：DOM 结构、CSS 计算值、几何测量（`getBoundingClientRect`）、控制台错误、网络 404、i18n 文案落地
- ❌ 验不了：任何需要帧循环的东西（教学推进、亮洞跟随、动画观感），也**截不了图**

凡是"看起来怎么样"的判断，只能交给用户真机跑一局。写报告时要老实说这一条。

### 关键 API

```ts
sim.update(delta, movement)        // delta 上限 0.05，探针用 1/20
sim.requestAttack()                // 独立入口，只看 running
sim.requestInteraction()           // 同上
sim.drainEvents()                  // 事件是 drain 语义，读完就没了
sim.enableCritters() / enableWolves()   // 生产环境等模型下载完才调，探针里要手动调
sim.start()                        // 不调的话 running=false，update() 直接 return
```

**时钟另有一道闸**：`clockStarted` 要玩家第一次真实移动才置 true，在那之前五轴不掉、相位不走、狼不动。探针里如果发现"跑了 300 秒什么都没发生"，八成是移动向量没过 `0.08` 的阈值。

## 3. 已经测出来的结论（别重新推导）

用户最初的问题是「大部分玩家走一走、挥一下武器就离开」。链条是：

1. **不是无聊，是被咬死。** 中位会话 72 秒，模拟层里不还手的玩家死在 75 秒，97% 掉血来自狗。
2. **开局 40 秒白天里挥刀必定打空** —— 最近可攻击目标 27 米外，一直挥刀的机器人第一次命中在 43.2 秒，即入夜之后 3 秒。玩家学到的是「挥刀没反应」，而那正是 30 秒后救他命的动作。
3. 修法是**世界改动**（出生点 6.3~7.8 米撒教学猎物、6.5 米撒教学枯木），第一次命中 **43.2s → 0.6s**。这个数字跟教学字幕无关。
4. 期间加过一版门禁式开场教学，被平台数据否掉（11 场里 4 场活不过 6 秒），1.0.13 减轻、1.0.14 整段删除。

### 当前瓶颈：第一夜（详见第 0 节）

模拟层实测（1.0.14，狼与猎物都 enable，攻击 0.55s / 行动 0.8s 机械节奏）：

```
只走不还手        死于  88s      失温 83s  首次挨咬 47s  掉血 89% 来自狗
走 + 一直挥刀     死于  86s      失温 83s  首次挨咬 47s  掉血 88% 来自狗
绕圈 + 挥刀       死于  89s
缩在营地 + 挥刀    死于 124s
走 + 刀 + 行动    死于 141s      ← 唯一点着火的一档（t=18s 点燃），也只多活 55 秒
完全不动          不死           ← clockStarted 没启动，五轴不掉，是探针假象不是玩法

入夜 t=40s，黎明 t=190s，第一夜攻营配额 5 只
```

**七种画像里没有一种活到黎明，全部死于狗咬。** 探针在 `tests/tmp/night1Wall.test.ts`、
`tests/tmp/nightSweep.test.ts`、`tests/tmp/whatIf.test.ts`、`tests/tmp/firstPayoff.test.ts`。

夜里战斗账：玩家攻 30、100 血；小狗 72 血 / 咬 9 / 防 1，大狼 **160 血 / 咬 20 / 防 7**。
打死一只大狼要 **7 刀**。失温后玩家 2.05 m/s，而小狗 3.65~4.4、大狼 4.2~4.85 —— **跑不掉也打不完**，
但把失温整条摘掉仍然全灭（见第 0 节），所以真正的约束是**时长**。

## 4. 数据怎么读（我在这里栽过）

### 别看中位数，看比例指标

我曾报「中位 20s → 50s」，四场新数据进来就掉回 25s。11 个数的中位数摆动极大。

按当前效应量算，要测出显著需要：

```
≥60s 占比（9% → 33%）    每版约 23 场
≤7s  占比（36% → 7%）    每版约 36 场
现在每版只有 11~15 场
```

**≤7 秒占比是小样本下最稳的指标**，它直接对应「第一眼像不像坏的」。

### 两批已有数据

```
1.0.12  n=11  中位 20s  [3,4,5,6,11,20,30,36,42,52,184]
1.0.14  n=15  中位 25s  [4,8,14,14,18,20,25,25,33,50,60,94,106,110,117]

           ≤7s 秒退   36% → 7%     ← 实打实的好转
           ≥60s 长局   9% → 33%
           中位数     20 → 25s     ← 几乎没动
           8~30s      27% → 47%    ← 中间那段变厚了：不再是打开就跑，但也没走远
```

## 5. 测量陷阱

1. **只看 computed z-index 判断遮挡** —— 数值是 13 > 12，绘制顺序却纹丝不动（`position: fixed` 本身创建层叠上下文）。要用 `document.elementFromPoint` 量真实命中。
2. **用外接矩形量圆按钮的重叠** —— 假阳性。圆按钮按「圆心距 −（半径和）」算。
3. **python 写文件用 `unicode_escape` 解码** —— 把 UTF-8 当 latin-1，中文全乱码，而 i18n 测试只查键集和占位符，查不出来。用字面量 + `encoding="utf-8"`。
4. **共享 `sharedWorld`** —— `GameSimulation` 会就地改动 world，复用会让用例结果取决于前面跑过几条。每条用例现造一个 `createWorld()`。

## 6. 别推翻的决定

| 决定 | 理由 |
|---|---|
| 不要再加门禁式教学 | 试过两版，数据两次否掉。价值在世界改动里，不在字幕里 |
| 幕布必须在 `#hud` 之下 | 层序写死：场景 → 幕布(1) → HUD(2) → 字幕(14) → 遮罩(20/35) |
| UI 高亮用逐元素压暗，不挖洞 | 右下四键彼此只隔 77~89px，照亮一颗的洞会把邻居一起照进去 |
| 捡柴 12 / 砍树 30 的价差 | 表达「这根柴好不好拿」，让玩家先捡光地上的再去砍树 |
| 行动键在拇指位 | 白天攻击不紧急（野狼要被激怒才追），紧急的是捡柴生火；行动键误触无代价，攻击误触扣劳力还惊动狗 |
