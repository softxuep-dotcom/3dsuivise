# 搬油三选一：开发交接

> 状态：设计确认，尚未实现。  
> 基线版本：1.1.25。  
> 核心目标：让“找到油 → 冒险搬回 → 立即变强 → 再拿下一桶”成为完整正反馈循环。

## 1. 已确认规则

1. 奖励触发点是**成功把油桶装进卡车**，不是刚从地上拿起油桶。
   - 避免玩家拿起、放下同一桶反复触发。
   - 奖励是完成一次危险运输后的结算。
2. 装到 `1/6、2/6、3/6、4/6、5/6` 时各触发一次三选一，一局共 5 次。
3. 第 6 桶不弹奖励；装满后直接进入上车发车流程，避免奖励来不及使用。
4. 每次展示 3 张卡，但**不是每局固定同三张**，使用受控随机卡池。
5. 奖励只在当前一局有效；死亡、通关、软重开后全部清空。
6. 选择界面打开时冻结模拟：昼夜、代谢、狼、移动与攻击全部暂停。
7. 选择不能跳过，键鼠支持 `1 / 2 / 3`，同时支持鼠标和触屏点击。

## 2. 玩家提出的三张核心卡

以下三张必须进入首版卡池。

### 2.1 军用肩带（搬运）

**文案：** 搬运减速惩罚减少 20%。

当前扛物倍率是 `0.54`，含义是减速惩罚为 `1 - 0.54 = 0.46`。这里减少的是“惩罚”，不是直接给移动速度加 20%。

```ts
carryScale = 1 - (1 - 0.54) * 0.8 ** stacks
```

| 层数 | 搬运倍率 | 相对未升级的搬运速度 |
| ---: | ---: | ---: |
| 0 | 0.540 | 100% |
| 1 | 0.632 | 117% |
| 2 | 0.706 | 131% |
| 3 | 0.764 | 142% |

- 最大 3 层。
- 使用递减收益，避免堆满后扛油比空手跑得还快。
- 只影响 `player.carrying !== null` 时的搬运惩罚，不改武器、护甲、饥渴和体温的移速系数。

### 2.2 加固内衬（战斗）

**文案：** 护甲 +2。

- 每层在当前装备防御力之外额外增加 2 点防御。
- 最大 3 层，总计最多 +6。
- 计算位置：`EquipmentSystem.defense()` 的装备防御之后。
- 不直接修改 `player.armor`，避免换装、降级或切线时重复累计。

```ts
finalDefense = equippedArmorDefense + perkStacks * 2
```

### 2.3 调匀呼吸（生存）

**文案：** 劳力恢复 +2/秒。

- 每层给移动、静止和休息三种状态统一增加 `+2/s`。
- 最大 3 层，总计最多 `+6/s`。
- 这是明确的平坦加值，应在护甲回复倍率结算后相加，保证一层永远正好是 `+2/s`。

```ts
staminaRegen = baseRegen * armorStaminaScale + perkStacks * 2
```

当前基础回复为：移动 `1.1/s`、静止 `1.6/s`、休息 `7.5/s`。

## 3. 建议补充的首版卡池

首版建议共 9 张卡：搬运、战斗、生存各 3 张。数量足够形成不同构筑，又不会把实现范围撑得过大。

### 3.1 搬运线

| ID | 名称 | 效果 | 层数上限 |
| --- | --- | --- | ---: |
| `carry-rig` | 军用肩带 | 搬运减速惩罚减少 20%，按剩余惩罚乘 `0.8` | 3 |
| `barrel-brace` | 护桶姿势 | 扛油时受到的伤害乘 `0.8^层数` | 2 |
| `empty-run` | 熟门熟路 | 装车后空手移速 +20%；首层 12 秒，第二层延长到 18 秒；再次装车刷新持续时间 | 2 |

设计目的：一张缩短返程、一张提高危险路线容错、一张缩短寻找下一桶的去程。

### 3.2 战斗线

| ID | 名称 | 效果 | 层数上限 |
| --- | --- | --- | ---: |
| `armor-plate` | 加固内衬 | 最终防御 +2/层 | 3 |
| `den-breaker` | 清巢老手 | 对仍守着油桶的守巢狼伤害 +25%/层 | 2 |
| `blood-rush` | 见血回神 | 击杀狼恢复体力；首层 +8，第二层 +13；4 秒内最多触发一次 | 2 |

设计目的：允许玩家投资战斗，一次性打开巢边三桶油的近路，但不把所有野狼和夜袭都变成免费资源。

### 3.3 生存线

| ID | 名称 | 效果 | 层数上限 |
| --- | --- | --- | ---: |
| `steady-breath` | 调匀呼吸 | 劳力恢复 +2/s/层 | 3 |
| `rationing` | 省着点吃 | 水分与饥饿消耗速度各乘 `0.88^层数` | 3 |
| `truck-supplies` | 后座补给 | 每次装车恢复体力 15、水分 12、饥饿 12；每层重复结算 | 2 |

`后座补给`在玩家选中时，要对**刚装好的这一桶立即结算一次**，随后每次装车继续触发。否则第一层会表现成“选了但什么都没发生”。

## 4. 受控随机规则

卡片使用模拟层自己的随机源，保证探针和测试可复现；禁止在 UI 中调用 `Math.random()`。

### 第一次奖励（1/6）

- 搬运、战斗、生存各抽 1 张。
- 三张顺序洗牌，避免玩家形成“左边永远是搬运”的肌肉记忆。

### 后续奖励（2/6–5/6）

1. 第一张：从玩家当前层数最多的路线中抽，保证能继续构筑。
2. 第二张：从另外两条路线中抽，保留转型机会。
3. 第三张：全池随机。

约束：

- 同一次不能出现两张同名卡。
- 达到层数上限的卡退出候选池。
- 三张至少覆盖两条路线。
- `den-breaker` 在五只守巢狼全部死亡后退出候选池。
- 同一组三张不能与上一桶完全相同。
- 路线层数相同时，以玩家最近一次选择作为主路线。

若过滤后不足三张，按“忽略主路线保证 → 忽略上一组防重复”的顺序放宽；绝不突破层数上限，也绝不发无效卡。

## 5. 数值边界

- 一局只有 5 次选择，因此所有叠加天然有总预算上限。
- 任何一条纯堆满都应形成明显人格：
  - 搬运：路线更短、更敢冒险。
  - 战斗：可以主动清巢换近路。
  - 生存：减少找补给和原地恢复的时间。
- 奖励不能赠送汽油桶、直接增加装车数或降低通关需求，否则会跳过核心玩法。
- 奖励不能永久写入 localStorage；记录板仍只保存最快脱出和最远油量。
- 首版不做稀有度、重抽、锁卡、永久天赋和局外货币。

## 6. 当前生存基线（实现时必须保留）

- 五项最大值均为 100。
- 开局体力 100、水分 80、饥饿 70、体温 22、劳力 100。
- 水分与饥饿仍按 `0.42/s` 消耗。
- 生肉恢复水分 `2–6`，熟肉恢复水分 `5–10`。
- 饥饿低于 18 时提示“快饿死了 · 打开背包吃块肉”。
- 水分和饥饿同时低于 18 时提示“又渴又饿 · 打开背包喝水吃肉”。
- 上述提示已覆盖 13 种语言，不要在奖励实现中回退或覆盖。

## 7. 推荐代码边界

### 模拟层

新增：

```text
src/game/simulation/FuelPerkSystem.ts
src/game/balance/fuelPerks.ts
```

建议状态：

```ts
type FuelPerkLine = "carry" | "combat" | "survival";
type FuelPerkId =
  | "carry-rig" | "barrel-brace" | "empty-run"
  | "armor-plate" | "den-breaker" | "blood-rush"
  | "steady-breath" | "rationing" | "truck-supplies";

interface FuelPerkState {
  stacks: Record<FuelPerkId, number>;
  pendingOffer: FuelPerkId[] | null;
  previousOffer: FuelPerkId[] | null;
  speedBurstSeconds: number;
  bloodRushCooldown: number;
}
```

职责：

- `FuelPerkSystem` 拥有卡片层数、抽卡、选择校验和运行时效果。
- `TruckSystem.loadCarried()` 只在装车完成后通知 owner 请求奖励。
- `GameSimulation` 提供 `getFuelPerkOffer()`、`chooseFuelPerk(id)` 和各子系统读取奖励效果的端口。
- 渲染层和 HUD 不能成为奖励状态的真相来源。

### 事件

新增事件建议：

```ts
| { type: "fuel-perk-offer"; loaded: number }
| { type: "fuel-perk-chosen"; id: FuelPerkId; stacks: number }
```

事件只负责通知表现层。具体三张卡由 HUD 调用 `simulation.getFuelPerkOffer()` 读取；选择必须回到 `simulation.chooseFuelPerk()` 校验。

### 现有公式接入点

- 搬运倍率：`GameSimulation.updatePlayerMovement()`。
- 最终防御：`EquipmentSystem.defense()`。
- 劳力回复：`SurvivalSystem.tick()` 中的 `staminaRegen`。
- 水分/饥饿消耗：`SurvivalSystem.tick()`。
- 守巢狼增伤、击杀恢复：攻击与狼死亡结算位置。
- 装车补给和空车加速：`TruckSystem.loadCarried()` 通知奖励系统处理。

## 8. UI 与暂停

- 使用 DOM overlay，不在 Three.js canvas 中画卡片。
- 新增 `fuelPerkOpen`，并并入 `HudController.isGameplayBlocked()`。
- 奖励选择不算平台离开游戏，行为与打开背包一致，不触发 `gameplayStop`。
- 弹出时取消点击移动目标，防止选择后人物继续沿旧路线跑。
- 卡片内容固定三层：名称、短句效果、当前层数/上限。
- 数值必须明确，例如“护甲 +2”，不要写“稍微提升防御”。
- 已有层数显示为 `Ⅱ → Ⅲ` 或 `2/3`，让玩家知道这是叠加而不是替换。
- 不允许 ESC 关闭或跳过；死亡、胜利、重开时强制清除弹层。
- 手机竖屏卡片纵向排列，横屏和桌面端三张横排。

工作标题建议：

```text
油已装车
选一项，为下一趟做准备
```

## 9. 音画反馈

- 先保留现有 `fuel-loaded` 装车音阶和车斗油桶落位动画。
- 动画落定后再弹选择，不要同一帧把装车反馈盖住；建议延迟 350–500ms。
- 选卡播放现有 `confirm`，并在卡片上做一次短促收束动画。
- 搬运线用沙黄、战斗线用锈红、生存线用青绿；颜色只辅助分类，文字仍需自足。
- 首版不新增 GLB、粒子或复杂镜头，避免奖励系统被美术依赖卡住。

## 10. 测试清单

### 模拟测试

1. 装第 1–5 桶各产生一次奖励，第 6 桶不产生。
2. 同一个油桶不能重复触发。
3. offer 固定 seed 可复现，且满足至少两条路线、无同名、无满层卡。
4. 选择不在 offer 内的 ID 会被拒绝。
5. 三张核心卡的数值公式逐层准确。
6. `后座补给` 选择当下立即结算，后续装车继续结算。
7. 所有奖励在软重开后归零。
8. 第 5 次选择后仍可正常装第 6 桶并通关。

### UI 测试

1. 弹层打开时世界冻结，选完立即恢复。
2. `1 / 2 / 3`、鼠标、触屏都能选择且只结算一次。
3. 320×568、375×812、740×340、1280×800 无越界和遮挡。
4. 13 种语言键集一致，长文案不会撑破卡片。
5. 死亡、胜利、暂停、广告、背包与奖励弹层不会互相叠死。

## 11. 推荐实现顺序

1. 建 `fuelPerks.ts`，只放卡表、层数上限和数值。
2. 建 `FuelPerkSystem.ts`，完成状态、抽卡和选择。
3. 接入三张核心卡，先用无样式测试弹层跑通完整闭环。
4. 接入另外六张卡。
5. 完成 DOM 卡片、输入和暂停。
6. 补齐 13 种语言、声音和动画。
7. 跑模拟测试、响应式截图和完整回归。

## 12. 验收标准

- 第一桶装车后 0.5 秒内出现一次清楚的选择。
- 玩家五次装车能形成至少三种明显不同的构筑结果。
- 连续两局不会稳定看到完全相同的三张组合。
- 所有卡片选择后立刻或在下一段核心行动中可感知。
- 没有卡片会绕过“亲自把 6 桶油运到车上”这一终局条件。
- 奖励系统不改变当前开局水分 80、饥饿 70 及现有低需求提示。
